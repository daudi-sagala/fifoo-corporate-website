# Owner’s launch checklist

## Corporate identity

- [ ] Confirm whether “Fifoo Incorporated” is the correct public name; it is provisional in this design.
- [ ] Enter the corporation’s exact registered legal name and actual incorporation jurisdiction.
- [ ] Enter a genuine business mailing address suitable for public display.
- [ ] Confirm the corporate/product relationship in the page copy is accurate.
- [ ] Compare the legal identity with the D&B/developer enrollment records.

## Contact readiness

- [ ] Create a business-domain mailbox or properly configured alias.
- [ ] Send a message from an unrelated outside account and receive it.
- [ ] Reply successfully with the corporate address as sender.
- [ ] Enter the telephone number and its international dialing format; test a call.
- [ ] Click every inquiry link and check its recipient and subject.
- [ ] Do not put passwords, API keys, personal identity documents, or an EIN on the website.

## Content and privacy

- [ ] Remove every bracketed placeholder through configuration/content edits.
- [ ] Keep the product’s launch status accurate; do not add nonworking store URLs.
- [ ] Confirm that the schematic day-map caption remains accurate; it is not an app screenshot.
- [ ] Review hosting/email providers and actual data-retention practices.
- [ ] Finish the corporate website privacy notice and its effective date; obtain appropriate legal review.
- [ ] Prepare the mobile app’s separate privacy policy and store disclosures outside this website template.
- [ ] Set the three launch review flags only when their corresponding work is complete.

## Build and publication

- [ ] Run `npm test` and `npm run build:production` successfully.
- [ ] Decide whether to enable public search indexing using `launch.allowIndexing`.
- [ ] Publish only the generated `site/` directory.
- [ ] Confirm there is no preview banner or draft privacy warning in the public build.
- [ ] Open the website over HTTPS on both the root domain and `www`.
- [ ] Test an incorrect URL and confirm it shows the helpful 404 page with working links.
- [ ] Check on real iPhone/Safari, Android/Chrome, and desktop browsers.
- [ ] Test keyboard navigation and larger browser text/zoom.
- [ ] Retain corporate access/recovery information privately, outside the website source.

The checklist and production gate are project safeguards, not a certification of legal compliance or app-store acceptance.
